# Brclio Robot 工程与执行语义

Brclio Robot 是纯浏览器应用。React 负责编辑与显示；独立 TypeScript 解释器负责移动、碰撞、收集与结果判断。学生程序是数据，参考解也是同样的数据，不存在另一条演示路线。

## 目录与职责

| 路径 | 职责 |
| --- | --- |
| `src/types/index.ts` | 关卡、指令树、程序、运行状态、播放器状态、草稿及通关记录的公共类型 |
| `src/data/levels.ts` | 12 个教学关卡与一个自由练习地图，包含提示、限制和参考程序 |
| `src/engine/validation.ts` | 不可信程序校验、全局节点 ID、参数、循环深度、函数引用与递归检测、积木计数 |
| `src/engine/interpreter.ts` | 惰性解释器与地图规则；不依赖 React、DOM、动画或计时器 |
| `src/engine/player.ts` | 串行播放、暂停、继续、单步、重置、速度与旧任务取消 |
| `src/features/editor/tree.ts` | 基于数组与 ID 的不可变插入、移动、复制、删除、容器查找 |
| `src/features/editor/ProgramEditor.tsx` | 积木库、主程序、循环容器、A/B 定义区、拖拽与非拖拽操作、撤销重做 |
| `src/features/simulator/RobotMap.tsx` | SVG 地图、原创机器人、星星、障碍、旗子、轨迹与当前位置 |
| `src/features/simulator/usePlayer.ts` | 将播放器快照接入 React，处理切关、页面离开与声音反馈 |
| `src/features/simulator/sound.ts` | 浏览器 Web Audio 生成的提示音，无远端音频素材 |
| `src/features/levels/LevelPicker.tsx` | 关卡选择、章节与完成标记 |
| `src/storage/index.ts` | localStorage 存取、损坏恢复、版本化 JSON 导入导出 |
| `src/App.tsx` | 关卡草稿、设置、任务提示、运行控制及导入导出流程的组合 |
| `src/components/` | SVG 图标、品牌机器人标记、对话框与帮助 |
| `src/styles/app.css`、`src/features/editor/editor.css` | 工作台与积木样式、响应式布局、焦点和减少动画 |
| `src/tests/`、`src/features/editor/tree.test.ts` | 执行、播放、关卡、保存与编辑数据操作单元测试 |

`docs/esther-app-template.html` 保存了用于改编的 Esther App 模板。实际应用由 React 组件构成，设计来源及协议说明保留在帮助与项目说明中。

## 数据边界

`Level` 是静态课程定义，包括网格尺寸、`start`、可选 `goal`、障碍、星星、可用指令、可选积木数量目标以及参考程序。内置课程主要为 5 至 8 格的地图；自由练习是固定的 8 × 8 地图。绘制与移动算法按关卡尺寸工作，关卡作者可以定义 4 × 4 至 12 × 12 的地图。第一版没有地图绘制编辑器。

`Program` 保存 `main: Instruction[]` 和 `functions: { A: Instruction[], B: Instruction[] }`。每个节点都有稳定且全程序唯一的 `id`。移动节点携带 `steps`，循环携带 `times` 和 `body`，函数调用携带 `fn: 'A' | 'B'`。数字是节点字段，不能脱离积木单独执行。

```json
{
  "main": [
    { "id": "start-call", "type": "call", "fn": "A" }
  ],
  "functions": {
    "A": [
      { "id": "walk", "type": "forward", "steps": 2 },
      { "id": "turn", "type": "right" }
    ],
    "B": []
  }
}
```

`RuntimeState` 保存当前机器人、已收集星星 ID、轨迹、已完成原子动作数、预算用量及结果。它与原始 `Level.stars` 分离。解释器读取独立程序与关卡副本，并向外返回状态副本，避免调用方修改正在执行的内容。

`PlayerSnapshot` 组合播放器状态与解释器快照。播放器的 `paused` 表示展示调度已暂停，解释器仍保留内部循环栈、调用上下文和多格动作进度。编辑器历史属于本次编辑会话，当前草稿才写入本地存储；切换关卡或刷新不恢复撤销历史。

`SaveData` 保存当前关卡 ID、按关卡 ID 分开的草稿、完成记录及设置。完成记录包括完成时间、实际存储积木数和原子动作数，不进行耗时排名。声音默认关闭，速度默认 1 倍，轨迹默认显示。

## 坐标、动作和成功规则

地图左上角为 `(0, 0)`，`x` 向右增加，`y` 向下增加。朝向只允许 `N / E / S / W`，分别表示北、东、南、西。SVG 只负责显示这些离散状态；机器人箭头与位置文字在关闭动画时仍指明朝向。

| 指令 | 原子语义 |
| --- | --- |
| 前进 1 至 9 格 | 每次原子动作沿当前朝向走一格，逐格检查边界、障碍和星星 |
| 后退 1 至 9 格 | 每次沿朝向的反方向走一格，朝向保持不变 |
| 左转 / 右转 | 原地转 90 度，坐标不变 |
| 重复 2 至 9 次 | 按顺序执行 `body`，然后进入下一轮；不预先展开全部循环 |
| 执行 A / B | 进入对应定义区，执行后返回原调用位置的下一条指令 |

进入星星格时自动收集；再次经过同一个星星 ID 不重复计数。发生碰撞或越界时，当前原子动作不会改变坐标，程序立即错误终止，剩余指令不再执行。错误快照保留发生问题的积木 ID 和多步进度，供编程板高亮。

只有**正常执行结束后，停在终点且收集全部星星**才通关。提前经过终点、离开终点、到达终点后撞墙都不通关。定义区没有调用就不执行，但运行前仍校验整个程序，包括未调用定义中的不合法指令、空循环和递归。

自由练习不进行关卡成功判断。正常结束显示“程序执行完成”；遇到边界或障碍仍给出具体错误。

## 编辑顺序与输入方式

执行顺序始终由数组顺序决定。主程序和每个循环体、函数体各自拥有密集数组；视觉换行不会重排这些数组。编号由数组索引及容器前缀生成，例如 `2.1` 或 `A.2`。

编辑器使用 `@dnd-kit/react` 和 `@dnd-kit/dom` 0.5.0 的 `DragDropProvider`、`useDraggable`、`useDroppable` 以及 Pointer/Keyboard Sensor。拖动落点映射为明确的 `{ container, index }`，之后调用相同的数据树操作。触屏从拖动区域启动，鼠标拖动需要达到移动距离；循环不能放进自己或自己的后代。

不拖拽时可以点击插入位置或积木库、选中积木后前移/后移、复制/删除、用目标容器菜单移入循环或移回主程序。键盘支持 Alt + 方向键调整位置、Delete 删除、Ctrl/⌘ + Z 撤销、Ctrl/⌘ + Shift + Z 重做。复制子树会为其所有节点生成新 ID。

运行、正在暂停和暂停期间锁定编辑。重置后才能修改。编辑历史最多保留最近 50 次更改；导入新程序后建立新的编辑历史。

## 串行调度与取消

`Interpreter.step()` 至多执行一个原子动作。对于“前进 3 格”，它保留节点内部进度，三次调用才完成移动。循环和调用上下文附着在 `ExecutionContext` 中，同时展示当前动作、函数调用位置和循环轮次。最后一个原子动作完成后，本次 `step()` 就判断结果，不要求额外点一次单步。

`Player` 只维护一个定时任务。每个原子动作由解释器计算新状态，再由 SVG/CSS 展示。默认下一动作的间隔为 `600 / speed` 毫秒，位置过渡短于该间隔。0.5、1、2 倍仅影响展示与调度时间。

“运行”创建新解释器并从关卡初始状态出发；执行中或暂停时重复调用 `run()` 不创建并发任务。“暂停”先进入 `pausing`，等待当前展示间隔结束后进入 `paused`，期间不会推进下一原子动作。“继续”复用原解释器；“单步”不创建自动播放定时器。

重置、切关、释放播放器会清除计时器，并递增内部代数标记。每个旧回调执行前核对标记，即使旧回调已经进入任务队列，也不能推动新关卡。React 清理调用 `dispose()`；`pagehide` 会停止本次执行。重置通过新的 SVG key 取消旧位置过渡。减少动画设置和系统 `prefers-reduced-motion` 只关闭展示过渡，不改变程序结果。

## 执行与输入预算

单次执行默认有 **2000 次解释器推进预算**。读取一条指令、进入循环的每一轮、执行一个移动或转向原子动作都会消耗预算；函数调用作为指令同样计费。例如单个“前进 3 格”消耗一次节点读取与三次原子动作，共 4 次预算，而动作计数是 3。

程序最多 **200 个存储节点**，包括主程序与 A/B 定义区；循环按结构最多嵌套 **两层**。函数复用不会提前展开为巨量节点。递归引用无论直接或间接都在运行前拒绝，预算则限制合法但很长的重复与函数组合。只有 A/B 两个函数，没有任意 JavaScript、`eval`、`new Function`、网络指令或用户资源地址。

## 保存、导入与安全恢复

本地存储键为 `brclio-robot.save.v1`。每关草稿相互独立。存储不可读、不可写、空间不足或 JSON 损坏时返回可展示的中文警告，不使页面白屏；单个草稿损坏只重建该草稿，其他有效进度保留。

校验故意区分三个场景：

| 场景 | 校验策略 |
| --- | --- |
| 运行 | 严格结构、参数、ID、指令范围、200 节点、两层循环、关卡积木数量、非空主程序/循环、有效函数引用及无递归 |
| 导入 | 同样严格，但允许空主程序与空循环作为编辑草稿；函数引用、递归和当前关卡限制仍校验 |
| 恢复本地草稿 | 保留结构与安全限制，允许尚未定义的函数调用、尚未整理好的递归关系和空容器；暂时忽略关卡 `maxBlocks`，避免丢失孩子超出目标的未完成构思；运行时重新严格检查 |

导入文件固定包含 `version: 1`、当前 `levelId`、`main`、`functions`。顶层、函数区和每种节点均使用字段白名单，拒绝未知字段、缺失/重复 ID、非法参数、非法函数、额外 HTML、代码或资源字段。导入校验函数只返回候选程序，失败不替换现有草稿。UI 在替换已有积木前确认；异步读取用版本标记避免切关或运行后落入旧导入结果。

UI 读取文件前限制为 100,000 字节；存储模块还对直接传入的 JSON 设置 250,000 字符上限。本地总存档上限为 2,000,000 字符。导出文件名包含产品名、关卡 ID 与日期。

数据仅保存在当前浏览器、当前站点来源中，不自动跨设备同步。清除浏览器数据、使用隐私模式或更换域名可能使旧进度不可用，可通过每关 JSON 导出备份。应用不采集儿童个人资料，不加载追踪脚本。

## 部署边界和第一版限制

`vite.config.ts` 使用相对资源基址 `./`。生产构建产物在 `dist/`，可上传到支持 HTTPS 的静态网站空间；核心编程、运行和保存不依赖后端。通过 HTTP(S) 服务访问构建产物，不能将 Vite 源码当作可双击运行的单 HTML 文件。

第一版没有账号、付费、排行榜、多人同步、硬件连接、AI 聊天、后台或云数据库；也没有地图编辑器、任意函数数量、超过两层的直接循环嵌套、条件分支、跨关卡程序自动转换与旧版本存档迁移。没有 Service Worker，因此首次访问仍需静态资源可达，不承诺安装式离线应用。当前草稿、完成状态和设置持久化，播放中的调用栈与撤销历史不持久化。
